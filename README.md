# YClients CRM — задачи администраторам + обзор для владельца

Надстройка над YClients. Тянет клиентов и историю визитов, считает периодичность посещений
и автоматически формирует **ежедневные задачи** администраторам: кому позвонить, кого напомнить,
кого записать, кого вернуть. Администратор отмечает результат звонка и заметку — всё ложится
в **ленту событий клиента**. Владелец видит сводку и может провалиться в историю по любому клиенту.

## Что внутри

- **Задачи** (для админов): список на сегодня с кнопками результата (записал / перезвонить / не ответил / отказ) и полем заметки.
- **Обзор** (для владельца): открытые задачи, обработано за день, конверсия в запись, работа каждого администратора.
- **Клиенты**: поиск, периодичность, прогноз следующего визита.
- **Лента событий**: визиты + звонки + заметки + задачи по клиенту в одной хронологии.
- **Telegram**: утренняя сводка админам «сегодня N задач» (опционально).

## Типы задач (движок правил `src/rules.js`)

| Тип | Когда создаётся |
|-----|-----------------|
| 🔔 Подтвердить визит | у клиента есть запись в ближайшие 1–2 дня |
| 🔄 Пора записать | прошёл прогноз следующего визита + 3 дня, будущей записи нет |
| ❌ Не пришёл | последний визит — no-show, клиент не перезаписан |
| 💤 Реактивация | не был дольше 2× своей средней периодичности |

Пороги настраиваются константами в начале `src/rules.js`.

## Запуск локально

```bash
npm install
npm start           # http://localhost:3020
```

Без токенов YClients приложение стартует в **демо-режиме** (сгенерированные клиенты и визиты) —
можно сразу посмотреть интерфейс. При первом старте с пустой базой синхронизация запускается сама.

## Подключение боевого YClients

1. Скопируйте `.env.example` → `.env`.
2. Заполните:
   - `YCLIENTS_PARTNER_TOKEN` — партнёрский (application) токен разработчика.
   - `YCLIENTS_USER_TOKEN` — пользовательский токен администратора.
   - `YCLIENTS_COMPANY_ID` — ID вашего филиала.
3. Перезапустите и нажмите **↻ Синхронизировать**. Как только все три заданы — режим `LIVE`.

> Эндпоинты YClients в `src/yclients.js` собраны по документации; на боевом аккаунте
> сверьте формат ответа `/records` и `/clients/search` — при расхождении полей правится
> только `normalizeRecord()` в `src/sync.js`.

## Telegram (опционально)

- Создайте бота у **@BotFather**, токен → `TELEGRAM_BOT_TOKEN`.
- Каждый админ пишет боту `/start`; узнайте их `chat_id` через
  `https://api.telegram.org/bot<TOKEN>/getUpdates` и впишите через запятую в `TELEGRAM_ADMIN_CHATS`.
- `PUBLIC_URL` — адрес дашборда, попадёт ссылкой в уведомление.
- Сводка уходит при каждом `/api/sync`. Для авторассылки по утрам повесьте cron на `POST /api/sync`.

## Деплой на Timeweb Cloud (как «План портных»)

- GitHub-репозиторий → Timeweb Cloud App Platform, backend/Node, автодеплой из `main`.
- Команда запуска: `node server.js`. Healthcheck: `/api/health`. Слушает `0.0.0.0`.
- Переменные окружения в панели Timeweb: `PORT=3000`, `DATA_DIR=/data` (persistent volume под SQLite),
  плюс токены YClients и Telegram.
- Открывается без VPN (в отличие от Railway).

## API

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/health` | статус + режим (demo/live) |
| POST | `/api/sync` | синхронизация + генерация задач + Telegram-сводка |
| GET | `/api/tasks?status=open` | задачи |
| POST | `/api/tasks/:id/action` | результат звонка + заметка |
| GET | `/api/clients?q=` | клиенты с периодичностью |
| GET | `/api/clients/:id/timeline` | лента событий клиента |
| GET | `/api/stats` | метрики для обзора |

## Структура

```
server.js            Express: API + раздача дашборда
src/env.js           загрузчик .env (без зависимостей)
src/db.js            схема SQLite (node:sqlite)
src/yclients.js      клиент YClients API + демо-данные
src/sync.js          синхронизация, расчёт периодичности/прогноза
src/rules.js         движок ежедневных задач
src/telegram.js      уведомления
public/index.html    интерфейс (задачи / обзор / клиенты / лента)
```
